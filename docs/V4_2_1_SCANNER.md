# V4.2.1 — 후보 계산 경량화 및 실행 진단

후보 순위는 거래활동·체결 수급·모멘텀만 사용하지만, 기존 hot_score는 호가 품질·예상 변동폭·변동성까지 계산했습니다. 거래 프레임 기반 계산을 공통 함수로 분리하여 순위 계산에는 필요한 항목만 사용합니다. 완성된 과거 프레임과 현재 프레임의 복사본을 가져온 뒤 순위 산술 연산을 수신 잠금 밖에서 수행합니다. 실제 진입/청산 판단은 기존 동기화와 전체 특성 계산을 유지합니다.

가상 259개 시장 × 1,800개 초별 프레임, 같은 PC에서 각 5회 측정한 중앙값: 기존 0.46465초, 보완 0.29828초(약 36% 감소). 네트워크, 실제 동시 체결, 느린 PC까지 포함한 지연 개선을 보장하는 수치는 아닙니다.

실행 시작 기록에 정확한 버전을 추가하고, 60초마다 후보 계산 시간·주문 판단 시간·최신 체결/호가를 모두 가진 후보 수·연결 상태를 기록합니다. 화면 데이터 상태에도 해당 수치를 표시합니다. 후보 계산 시간에는 순위 계산만, 주문 판단 시간에는 계정 조회와 주문 처리도 포함됩니다. 마지막으로 완료한 작업의 소요시간이며 첫 작업 전에는 0입니다. 스트림 전체의 최근 수신과 개별 종목의 신선도는 다르므로 두 지표를 함께 확인해야 합니다.

검증: 기존 127개 테스트에 점수 일치(3개 창 길이), 계산 중 체결 수신/복사본 불변, 지연 종목 제외, 진단 기록 제한을 추가해 총 133개 테스트. 공개 300초 기록의 1,020개 진입 판단 지문은 V4.2.0과 동일(`d364e945e76342a4290dece73459225e9d8d7a3a14615f53c400b83db6ac8e2e`), BUY 2회. 이번 버전은 진입·청산 기준을 바꾸지 않습니다. 실거래 주문 없이 검증했습니다.

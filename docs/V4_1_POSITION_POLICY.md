# V4.1.0 — 진입과 보유 판단 분리

## 문제와 원인

V4.0.7은 매수 직후 `수급 약화: HoldQ=...`로 청산될 수 있었습니다. `evaluate_position`은 신규 진입용 Activity/Aggression/Book/Momentum percentile의 기하평균을 그대로 HoldQ로 사용하고, 0.36 미만을 두 번 관측하면 매도했습니다.

이 점수는 **지금 새로 진입할 만큼 수급이 이례적으로 강해지는가**를 나타냅니다. 보유 포지션의 근거가 실제로 반전됐는지는 다른 질문입니다. 매수 우위 호가가 유지되더라도 imbalance의 증가가 멈추면 book factor가 급락합니다. 가격이 잠깐 평평해져 short return이 0이 되어도 momentum factor가 0이 됩니다. 기하평균은 한 항목만 0에 가까워져도 크게 낮아지므로, 새로운 매수 신호의 소멸이 곧바로 매도 신호가 되었습니다. 같은 데이터에 대한 반복 평가도 두 번의 악화로 계산됐습니다.

또한 여러 후보의 수수료 조회나 앞선 주문 처리가 끝난 후, 이전에 계산한 진입 신호를 재사용했습니다. 주문 직전 호가의 수신 시각만 최신이라고 해서 앞서 계산한 매수 근거가 여전히 유효한 것은 아닙니다.

## 변경

### 보유 판단

보유 판단은 신규 진입 percentile 대신 방향성 있는 체결 수급, 호가 잔량, 가격 움직임을 사용합니다.

```text
flow_support  = clamp((aggression + 1) / 2)
book_support  = clamp((imbalance + 1) / 2)
noise         = max(spread, realized_30s × 0.25, round_trip_cost × 0.25, 0.000001)
price_support = 0.5 + 0.5 × tanh(short_return / noise)
HoldQ         = 0.4 × flow_support + 0.3 × book_support + 0.3 × price_support
```

일반 수급 청산은 아래 3개 중 2개 이상이 부정적으로 바뀌고, 최소 5초 동안 3회 이상의 새 관측에서 유지되는 경우입니다.

- aggression < -0.10: 매도 체결 우위
- imbalance < -0.10: 매도 호가 잔량 우위
- short_return < -noise: 현재 스프레드·변동성·비용을 고려한 가격 하락

새 관측은 체결 프레임과 호가 프레임의 초가 **둘 다** 진행되어야 합니다. 같은 프레임을 반복 조회해도 확인 횟수가 늘지 않고, 새 관측이 없는 호출에서 청산을 확정하지 않습니다. 신호 회복, 데이터 지연, 3초를 넘는 관측 공백, 호가 초기화는 확인 상태를 초기화합니다. 청산 근거를 5초간 검증하는 것이며 모든 포지션에 일률적인 최소 보유시간을 부여하는 기능은 아닙니다.

이 중립 구간, 가중치와 확인시간은 급한 반응을 줄이기 위한 해석 가능한 초기 정책입니다. 최적 수익 파라미터로 검증됐다는 뜻은 아닙니다.

### 가격 위험과 시간 청산

- Emergency Stop은 확인시간·데이터 워밍업보다 먼저 판단하며 기존 손절 거리를 확대하지 않습니다.
- Adaptive Trailing은 신규 수급 반전 확인을 기다리지 않습니다. 최신 체결 가격이 있으면 호가가 지연되어도 작동합니다.
- 체결 가격 자체가 오래된 경우 일반 판단을 기다리며, 추정된 새 가격으로 청산하지 않습니다.
- 기대 보유시간의 1.5배가 지났는데 움직임이 충분하지 않고 가격 진전도 없으면 시간 청산합니다. 호가가 매수 우위라는 이유만으로 무기한 보유하지 않습니다.

### 주문 직전 신호 재확인

후보별 주문금액을 계산하기 직전에 `evaluate_entry`를 다시 호출합니다. 이미 소멸한 신호라면 주문을 내지 않고 재확인 사유를 표시합니다. 가격/수급 데이터가 계속 변하는 시장에서 REST 접수 시점까지 동일한 상태를 보장할 수는 없습니다.

### 관측성

화면 진단 영역에 보유 경과시간, HoldQ, 반전 지표 수, 확인 횟수를 표시합니다. `position_state` 이벤트에도 주기적으로 기록하여 다음 분석에서 청산 전 상태를 확인할 수 있습니다.

## 매수를 강제로 늘리지 않는 이유

진입 quality, 비용 2배 조건, Health, market regime, 3초 신규 주문 데이터 안전장치, Best+IOC 유동성·주문 복구는 유지합니다. ‘매수 안 함’은 시세 지연, 비용 부족, 신호 소멸을 구분해야 합니다. 이번 수정에서 대기 상태를 해제하기 위해 손실 기록을 지우거나 계정 잔고를 변경하지 않습니다.

## 검증

- 기존 전체 회귀 테스트에 13개 테스트를 추가했습니다. 총 122개 로컬 테스트 통과.
- 실제 원시 형식의 체결·호가를 넣은 회귀 테스트에서 매수 우위 호가가 평평해지면 이전 HoldQ는 0.36 미만으로 반복 하락하지만 V4.1은 보유합니다.
- 지속 반전, 한 지표만 약화, 같은 데이터 반복 조회, 회복/지연/관측 공백 초기화, 즉시 손절, 추적 청산, 시간 청산, 주문 직전 신호 소멸을 검증했습니다.
- 공개 시장 300초 기록에서 8,437개 레코드를 저장했고 누락·WebSocket 오류·실제 주문은 0건입니다.
- 같은 기록을 V4.0.7과 V4.1로 replay한 1,020개 진입 결정이 모두 같았습니다. BUY 결정은 각각 2회였고 결정 지문은 `e6d03c7440ca759cce5299529b105bb541b5b819a9b7f1451303b368de4b29b7`로 일치했습니다.
- 이 기록의 시장별 첫 BUY 신호를 가상의 보유 시작점으로 고정한 단일 RAY 사례에서, 이전 정책은 3.25초 후 수급 약화로 청산 신호를 냈습니다. V4.1은 15.281초 후 Adaptive Trailing 신호를 냈습니다.

마지막 비교는 **주문 체결을 모델링하지 않은 한 건의 정책 재현**입니다. 실제 수익, 매도 체결가격, 평균 보유시간 또는 장기 OOS 성능을 입증하지 않습니다. 짧은 녹화로 파라미터를 최적화하지 않았습니다. 향후 여러 시장 구간의 체결 모델을 포함한 장기 검증이 필요합니다.

## 배포

패키지 및 Release 버전은 V4.1.0입니다. 기존 Windows/Linux CI와 공개 시세 smoke, Windows 실행파일 빌드를 거쳐 배포합니다. API Key, 관리 수량과 기존 durable order journal을 보존합니다. DB 스키마 변경은 없습니다.
